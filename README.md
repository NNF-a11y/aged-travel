# 拾光出行 · 适老化老人出行助手

一个面向老年人的单页出行助手。整个应用只有一个 `index.html`，CSS 与 JavaScript 全部内联，不依赖任何框架、外部图片或 CDN，双击即可打开。

页面由五个模块组成：**场景预览**、**路线跟踪**、**子女代管**、**极简模式**、**个人中心**，通过顶部导航切换，默认显示「场景预览」。

## 五个模块

### 1. 场景预览

- 三张景区卡片：西湖苏堤、故宫中轴线、社区公园。
- 每张卡片上方是用 CSS 渐变绘制的风景图，不加载任何图片文件。
- 彩色徽章标注适老信息：♿ 无障碍通道、🪑 休息长椅、🚻 无障碍卫生间、☎ 求助点。
- 点「查看详情」展开该景区的无障碍设施分布、休息点数量、卫生间与求助点位置；再点一次收起。

### 2. 路线跟踪

- **路线进度**：顶部卡片显示今日路线「苏堤春晓 → 雷峰夕照」的完成度（进度条 + 百分比，读屏软件可读出 aria-valuetext），并列出剩余路程与预计时间；下方四个站点用状态区分——已到过的打勾、正在前往的高亮并显示剩余距离、未到的显示预计时间。
- **当前位置**：用 `navigator.geolocation.watchPosition` 持续监听位置，经纬度保留 6 位小数，并显示「最后更新」时间和精度；定位信号短暂波动时会保留上一次位置，不会把已经显示的位置清空。
- **实时位置地图**：示意图画出湖面、苏堤、北山街、南山路、林间步道、建筑与树丛，并标注游客中心、无障碍卫生间、长椅区、出入口、压堤桥五处适老点位。定位成功后出现「您在这里」的绿色标识与半透明精度圈；位置移动时标识跟随移动并留下轨迹。地图带指北针与 0–200 米比例尺，按 1 像素约 2 米换算，只表示相对位移。
- 拒绝授权、信号差或超时时给出对应提示，并显示「查看示例位置」按钮；示例位置会明确标注「示例位置 · 仅用于预览地图布局，不是真实定位」。
- **一键紧急求助**：整行宽的红色按钮（高度 84px、字号约 24px）。点击先弹确认框，确认后显示「求助信号已发送，已通知紧急联系人」并记录发送时间，同时把记录追加到下方清单。
- **安全播报**：3 条记录（已进入景区范围 / 已休息 10 分钟 / 偏离推荐路线），每条带时间戳和状态颜色（正常、提醒、警告）。

### 3. 子女代管

- 顶部说明：此页面供子女协助老人管理行程，预订与位置播报会同步到老人端。
- 行程预订表单：景区下拉框、出行日期、同行人数、是否需要无障碍协助复选框，以及「提交预订」按钮。
- 提交时做前端校验：景区与日期必填，缺失时在字段下方提示并聚焦到第一个错误项；校验通过后显示「预订已提交」及本次预订摘要（景区、日期、人数、协助方式与后续联系说明）。
- 下方「安全播报接收」同步展示老人端的 3 条播报，带时间戳和状态标签。

### 4. 极简模式

- 「开启超大字体」开关：把根字号从 18px 放大到 24px，五个模块的 rem 尺寸同步放大。
- 「高对比度模式」开关：整页切换为黑底黄字，适合弱视或在强光下使用。
- 「🎤 语音搜索」大按钮：浏览器支持 `webkitSpeechRecognition` / `SpeechRecognition` 时启动中文语音识别，识别结果显示在下方文本框中；不支持时提示「当前浏览器不支持语音搜索，请使用 Chrome 或 Edge」。

### 5. 个人中心

- 未登录时显示登录引导和「登录 / 注册」按钮；登录后可看到大头像、脱敏手机号（139****1111）和加入时间。
- **个人头像**：点头像或「更换头像」可以打开选择面板，内置三款手绘 SVG 头像（桂英奶奶、老周爷爷、山野），选择后立即生效，保存在浏览器 `localStorage` 里，刷新后仍然保留。
- 三张信息卡：紧急联系人（点「拨打电话」直接调起手机拨号）、我的行程（子女代管提交的预订会自动出现在这里）、无障碍偏好（实时显示超大字体与高对比是否开启，并可一键跳转到极简模式）。
- 登录：输入手机号，点「获取验证码」后输入短信里的 6 位数字即可登录；登录状态、头像与预订记录保存在浏览器 `localStorage` 中，点「退出登录」清除登录状态。也可以点「先随便逛逛」不登录直接体验。

## 本地打开方式

最简单的方式是直接双击 `index.html`。但要注意：定位和语音识别在多数浏览器里要求安全上下文（HTTPS 或 localhost），`file://` 下可能被拒绝。想完整试用这两项功能，建议起一个本地静态服务器：

```bash
# 任选一种，在项目目录下执行
python -m http.server 8080
# 或者
npx serve .
```

然后浏览器访问 <http://localhost:8080>。如果直接双击打开时定位被拒绝，路线跟踪页会显示「查看示例位置」按钮，点一下也能看到地图和位置标识。

## 部署到 GitHub Pages

1. 新建一个 GitHub 仓库，把 `index.html` 和 `README.md` 推送到仓库根目录（入口文件名必须是 `index.html`）。
2. 打开仓库的 **Settings → Pages**。
3. 在 **Build and deployment** 里把 **Source** 选为 `Deploy from a branch`。
4. **Branch** 选择 `main`（或 `master`），目录选 `/ (root)`，点击 **Save**。
5. 等一两分钟，访问 `https://<你的用户名>.github.io/<仓库名>/` 即可。

因为是纯静态单文件，不需要任何构建步骤；GitHub Pages 默认提供 HTTPS，定位和语音识别都能正常工作。

> 更新已上线的页面：重新上传覆盖 `index.html` 即可，等约一分钟；如果浏览器还显示旧版，按 Ctrl+F5 强制刷新，或在地址后加 `?v=2`。

## 前端实现范围

以下能力在当前版本中是纯前端实现，接入后端后才能对外提供服务：

1. **定位与轨迹**只在本机计算，不上传、不落库；关闭页面后轨迹即消失。
2. **紧急求助**只把记录写入本页清单与子女端播报列表，不会真的发送短信或推送，也没有拨打 110/120。
3. **预订**不产生真实订单与支付，记录存在浏览器 `localStorage`，仅用于展示流程。
4. **登录**不校验真实短信验证码，任意 6 位数字均可通过；账号信息只存在本机浏览器。
5. **语音识别**依赖浏览器的 Web Speech API，Chrome / Edge 体验最好；不支持时会提示并给出替代操作。

真实上线还需要：位置与轨迹的服务端存储、紧急求助的短信/推送与急救联动、订单与支付、子女账号与权限体系、以及 HTTPS 环境。
